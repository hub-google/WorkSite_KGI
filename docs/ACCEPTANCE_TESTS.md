## 0. 驗收基準與執行規定

- 必須在**原版 reference**與候選版使用相同 Git commit／data 版本、同一 browser、zoom=100%、時區 Asia/Taipei、同一 viewport；僅文字描述「看起來相同」不算通過。
- Golden source：主文件 [index.html](../index.html)、[REFERENCE_STYLE.css](REFERENCE_STYLE.css)、[REFERENCE_MARKUP.html](REFERENCE_MARKUP.html)、五個路由載入殼及 data/ 檔。
- 建議桌面 1440×900、1920×1080；手機 390×844、430×932；平板 820×1180；可補 900px、1040px 分界前後 1px 驗證。
- 完成每次測試記錄：測試 ID、commit SHA、URL、輸入條件、選定組織／類別、預期值、實得值、是否通過、畫面截圖與失敗原因。不要只截圖不記數值。
- 關鍵數值比較採**未格式化的完整精度**；顯示層檢查千分位與百分比小數一位。
- 不允許以修改預期數字、硬編碼總計、隱藏失敗欄位、動態重抽亂數等方式通過測試。
- 本文件的數據 fixture 只對現有來源快照有效；更新來源時應版本化 fixture 並說明變更。

### 5.3 組數／新人數：只顯示在組織層（不可按職域列拆分）

固定資料檔：[data/organization-metrics.json](../data/organization-metrics.json)。現行來源 1,728 筆索引、1,724 個完整路徑去重人員、127 個通訊處；依通訊處派 1～2 名示範組長，以及固定 13% hash 模擬新人。**數值固定，獨立於職域與績效月份。**

| 區域中心 | 組數 | 新人數 |
|---|---:|---:|
| 北一區域 | 29 | 45 |
| 北二區域 | 27 | 25 |
| 桃竹區域 | 22 | 34 |
| 中嘉區域 | 33 | 49 |
| 台南區域 | 19 | 24 |
| 高屏區域 | 26 | 34 |
| **通路總計** | **156** | **211** |

- ORG-01：表頭確切順序必須是「**區域中心、組數、新人數、職域、職域數……**」，不是把組數／新人數放在職域右邊。
- ORG-02：每個區域中心的組數、新人數**各僅一個跨列合併儲存格（rowSpan）**，與區域中心同樣跨越全部職域列及該區域小計。**任何單獨職域列都沒有組數／新人數值**。
- ORG-03：通路總計亦只有一組 156／211 的合併儲存格，不在每個類別重複。
- ORG-04：每個中心下鑽業務區後的組數、新人數加總應精確等於中心；同理業務區→通訊處→業務員。
- ORG-05：六區組數之和 29+27+22+33+19+26 = **156**；新人數之和 45+25+34+49+24+34 = **211**。
- ORG-06：職域篩選從「全部」改成只勾「闔家安康」時，組數／新人數不可被縮小到某類別值；它們是組織編制指標。
- ORG-07：將月份由 202601～202610 改成 202601～202609，組數／新人數不變（目前固定組織名冊模擬）；職域 FYC/FYN/保費仍會變動。
- ORG-08：在「顯示／隱藏指標」取消「組數」勾選時，整欄（含表頭與 rowSpan 儲存格）消失，保留新人數；取消新人數後，「職域」緊接「區域中心」，勾回後順序復原。
- ORG-09：點「組數」「新人數」表頭排序時，根據組織層級的真正數據排序，不是按職域的虛擬值排序；恢復名稱排序後六區順序符合 SORT-01。
- ORG-10：刷新／切換路由回績效，已載入的 JSON 應保留相同數值；不得每次隨機變動。
- ORG-11：子集合小計與父層精確一致；**不應**以各職域加總計算組數新人數。
- ORG-12：載入組織模擬 JSON 失敗／人員索引不合法時顯示錯誤，不能顯示虛假數字。

### 5.4 去重指標／模擬指標

- DISTINCT-01：同一業務員跨兩個職域，單類別經營人數各有 1，但組織總計去重仍為 1。
- DISTINCT-02：同一 B 職域代碼跨組織，在全通路只計 1；各子組織 DISTINCT 合計可能不等於通路 DISTINCT（現有曾差 1），不能硬湊總計。
- DISTINCT-03：達標經營人員結果按**人員唯一 key**固定；父組織達標去重數不得小於任何一個子集合。
- DISTINCT-04：達標職域在同一 B code 跨組織不能重抽，依固定 hash。
- DEMO-01：相同 row 執行整體 FYC 3～6 倍逐筆 round，同一基準 repeat 100 次值不變。
- DEMO-02：FYN/保費整體 KPI 為職域業績 ×5。
- DEMO-03：若 FYC 原始業績含負值，JS Math.round 的負數行為不能被 Python round / 四捨五入替代。
- DEMO-04：同類別多組織的模擬整體 FYC sum 要能對回以相同 row 計算的父範圍結果。
- REAL-01：FYN 淨值 >0 人才算實動，必須先按人加總，不能只看是否有一筆正 FYN。
- REAL-02：無來源的 group/claims/line 等 KPI 顯示「—」而非假的 0。

## 8. 非功能與安全

- SAFE-01：在 GitHub Pages 的公開 data 下搜尋任何正式密鑰、Bearer token、明文個資或保單完整號碼，結果須為零。
- SAFE-02：不得將靠 CSS hidden 的欄位當成授權；正式版需另有 SSO、角色與資料行級授權。
- SAFE-03：manifest/shard 載入失敗時明確顯示錯誤，不生成假的績效。
- SAFE-04：DecompressionStream 不可用時顯示相容性說明，不能默默回零。
- PERF-01：載入 22 個 shard 時不可有 JS 例外、無限 loading、反覆重複 append。
- PERF-02：同一個 session 切換五頁，績效資料不應每次重新讀 22 個 shard（懶載入只一次）。
- PERF-03：鍵盤可 focus 選單、checkbox、輸入、排序和 dialog 關閉按鈕。
- PERF-04：頁首／側欄／表格在 390px 手機寬度不造成無法操作的遮蔽。
- PERF-05：不同緩存版本下確保 GitHub Pages 依新提交部署，不可把舊快取畫面當成驗收成功。

## 9. 驗收交付包最低內容

1. 產品原始碼、版本 SHA、建置／部署說明、route 列表。
2. 固定資料 fixtures 與數值驗證結果（包括 null、負值、同 ID 重複）。
3. 各功能直連／切頁／返回／刷新測試紀錄。
4. 桌機、手機重要視圖的 **reference vs candidate** 截圖和差異圖。
5. 所有數值及 KPI 邊界 PASS／FAIL 報告，必須列出「尚未測試」項目，不得用「完成」掩蓋。
6. 安全限制、模擬來源、待開發功能總結。
7. 每次更版同步更新 [PRD](../PRD.md)、[IMPLEMENTATION_SPEC](IMPLEMENTATION_SPEC.md)、[DATA_CONTRACT](DATA_CONTRACT.md) 與本驗收清單。
